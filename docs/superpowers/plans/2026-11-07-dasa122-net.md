# dasa122.net Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use `- [ ]` syntax for tracking.

**Goal:** Ship `dasa122.net` — a personal showcase site whose centrepiece is a news feed — with an Authentik-gated admin panel, GitHub and LinkedIn feed integrations, and a deployment of two containers behind a single public hostname.

**Architecture:** A Bun workspaces monorepo. `packages/contract` holds the oRPC contract, the hand-written zod wire schemas, the shared error map, and the typed client factory — it is the single source of truth for every request and response shape. `packages/ui` holds the design-system primitives only. `apps/api` serves the oRPC router from `Bun.serve` at `/api/rpc` (typed RPC) and `/api/*` (REST + OpenAPI), and owns the Drizzle schema, the Authentik OIDC flow, and the feed-sync workers. `apps/web` is a TanStack Start SSR app served by `srvx`. Coolify's Traefik splits one hostname: `Host(dasa122.net)` → web:3000, `Host(dasa122.net) && PathPrefix(/api)` → api:3001.

**Tech Stack:** Bun 1.4.4 · TypeScript 7.0.2 · React 19.3.1 · TanStack Start 1.169.4 / Router 1.170.46 / Query 5.107.1 / react-router-ssr-query 1.167.3 · oRPC 1.16.2 · Drizzle ORM 0.45.4 + drizzle-kit 0.31.11 over `bun:sql` · PostgreSQL 18.6 · Tailwind CSS v4.3.5 · Biome 2.6.6 · Turborepo 2.11.10 · Vite 8.3.6 · srvx 1.0.8 · marked 18.1.3 + shiki 4.6.0 · zod 4.6.7 · bun:test

**Spec:** `docs/superpowers/specs/2026-11-07-dasa122-net-design.md`

## Global Constraints

- Runtime and package manager is **Bun 1.4.4 only** — never npm, pnpm, or yarn.
- TypeScript **7.0.2**, `strict: true`.
- Bun workspaces (`apps/*`, `packages/*`) + Turborepo 2.11.10 + Biome 2.6.6 + lefthook 2.2.2.
- Drizzle ORM **0.45.4** + drizzle-kit **0.31.11** over Bun's built-in Postgres client (`bun:sql`) via `drizzle-orm/bun-sql`. **Never** postgres-js, **never** node-postgres.
- oRPC **1.16.2** — `@orpc/contract`, `@orpc/server`, `@orpc/client`, `@orpc/tanstack-query`, `@orpc/openapi`. **Never** Hono.
- The contract lives in `packages/contract` and is the **only** source of request and response shapes. Wire schemas are **hand-written zod** in `packages/contract/src/domains/`, never derived from Drizzle types.
- The root contract is `oc.errors(apiErrors).router({ ... })`. The server side is `implement(appContract).$context<ApiContext>()` followed by `base.router({ ... })`, which type-checks the implementation against the contract.
- List responses are `{ items, total }` — there is **no response envelope**.
- **No JWT is ever handed to the browser.** The session id is an opaque random string.
- Zod 4.6.7 — `z.uuid()` for ids, `z.iso.datetime()` for ISO datetimes, `z.record` requires two arguments.
- Biome: `useImportExtensions` **off**; `noNodejsModules` **error** for all app and package sources; `noUndeclaredDependencies` **error**; `useSortedKeys` **off** for route files (TanStack Router route-property order is semantic) and for Drizzle schema files (column order is semantic).
- The web build command is **`bun --bun vite build`** — the `bun --bun` prefix is mandatory. Output is `dist/client/` + `dist/server/server.js`. There is **no** `.output/` directory and **no** Nitro.
- The web build output **must stay at `apps/web/dist`** — the server bundle resolves `react`, `react-dom`, and `@tanstack/*` as externals by walking up from its own directory.
- `srvx` is invoked by its **direct binary path**, never through `bun x` (which would fetch from the network at container start).
- Migrations live in `apps/api/src/database/migrations/` and are applied **at boot** with `migrate(db, { migrationsFolder: 'src/database/migrations' })`. The API container's working directory is `/app`, so the release image must contain them at `/app/src/database/migrations`.
- Migrations are generated by drizzle-kit **only**. Never hand-edit generated SQL or snapshot files.
- oRPC paths: typed RPC `/api/rpc/*`, REST `/api/*`, OpenAPI document `/api/doc/openapi.json`, Swagger UI `/api/doc/swagger`.
- The public origin is `https://dasa122.net`. Traefik splits `Host(dasa122.net)` → web:3000 and `Host(dasa122.net) && PathPrefix(/api)` → api:3001.
- The session cookie is **host-only for `dasa122.net`** and is never sent to `auth.dasa122.net` or any other subdomain.
- The browser oRPC client uses `${window.location.origin}/api/rpc` with `credentials: 'same-origin'`. A relative base is **never** passed to the oRPC link codec — it builds a `URL`, and the browser `URL` constructor rejects a relative base.
- The web app **must** implement `/healthz` as a liveness check with **no** database dependency.
- Local development databases are `dasa122_net` and `dasa122_net_test` on `localhost:5432`. **Never** touch `filc_359_filcdev_hu`.
- Secrets never appear in a log line. Provider error bodies are read to at most 4 KB and reduced to a truncated `error` / `error_description` pair.
- Three typefaces only: **Instrument Serif** (display), **Instrument Sans** (UI/body), **JetBrains Mono** (metadata). **Never** Inter.
- One accent only — ember `oklch(0.58 0.17 45)` — used **only** for interactive affordances and source badges, never for decoration.
- Motion is 400 ms `cubic-bezier(0.2, 0, 0, 1)` fade + 8 px rise. No springs, no parallax. `prefers-reduced-motion` disables it.
- Implementation happens on a branch off `main`, **never directly on `main`**.

## Review Focus

- A post whose `published_at` is in the future, or whose `status` is `draft`, must never appear in `posts.list` and must return `NOT_FOUND` from `posts.bySlug`.
- Two posts whose titles slugify to the same string must not collide: the second publish must receive a distinct slug rather than failing on the unique index.
- The same GitHub event arriving twice — a re-sync, an overlapping scheduled run, or a manual sync during a scheduled one — must produce exactly one feed item.
- `AUTHENTIK_CLIENT_ID` or `AUTHENTIK_CLIENT_SECRET` empty must not stop the API from booting or serving public routes; only the admin login may return 503.
- Markdown containing `<script>`, `<iframe>`, or a `javascript:` URL must be stripped before the HTML reaches `dangerouslySetInnerHTML`.

import { ORPCError } from '@orpc/server'

export function assertSameOrigin(request: Request, publicOrigin: string): void {
  if (request.method === 'GET' || request.method === 'HEAD' || request.method === 'OPTIONS') return
  const origin = request.headers.get('origin')
  if (origin === null) return
  if (origin !== publicOrigin) {
    throw new ORPCError('FORBIDDEN', { message: 'Cross-origin request rejected' })

}

    await context.db.execute('SELECT 1')
    database = 'up'
  } catch {
    database = 'down'

    status: database === 'up' ? ('ok' as const) : ('degraded' as const),
    database,

})

- [ ] **Step 5: Write `apps/api/src/auth/pkce.ts`**

- [ ] **Step 7: Write `apps/api/src/auth/oidc.ts`**

`discover` fetches `${issuer.replace(/\/$/, '')}/.well-known/openid-configuration` and returns the parsed `OidcDiscovery`. It throws `Error('discovery_failed')` on a non-2xx response.

`buildAuthorizeUrl` returns `${authorization_endpoint}?` plus URLSearchParams of `response_type=code`, `client_id`, `redirect_uri`, `scope`, `state`, `nonce`, `code_challenge`, `code_challenge_method=S256`.

`exchangeCode` POSTs to `token_endpoint` with `application/x-www-form-urlencoded` body containing `grant_type=authorization_code`, `code`, `redirect_uri`, `client_id`, `code_verifier`, and HTTP Basic auth of `clientId:clientSecret`. On a non-2xx response it reads **at most 4096 bytes** of the body, calls `parseTokenErrorBody`, and throws `Error(`token_exchange_failed: ${parsed.error}`)`. On success it returns the parsed `TokenResponse` and throws `Error('missing_id_token')` when `id_token` is absent.

`parseTokenErrorBody` parses JSON, takes `error` (truncated to 64 characters) and `error_description` (truncated to 200 characters), strips control characters from both, and returns `{ error, errorDescription }`. A body that is not JSON returns `{ error: 'unknown_error', errorDescription: null }`.

- [ ] **Step 8: Write `apps/api/src/auth/jwks.ts` and `apps/api/src/auth/id-token.ts`**

`jwks.ts` exports `getJwks(discovery, fetchImpl?)` which fetches `discovery.jwks_uri` and returns `{ keys }`. It caches the result in a module-level variable for **1 hour** and re-fetches after that. A failed fetch throws `Error('jwks_fetch_failed')`.

`id-token.ts` exports two functions:

- `decodeIdTokenPayload(idToken: string): unknown` — splits on `.`, base64url-decodes the middle segment, and `JSON.parse`s it. Throws `Error('id_token_malformed')` on failure.
- `validateIdTokenClaims(args: { claims: Record<string, unknown>; issuer: string; audience: string; nonce: string | null; nowSeconds?: number }): { ok: true } | { ok: false; reason: 'issuer_mismatch' | 'audience_mismatch' | 'nonce_mismatch' | 'expired' | 'missing_claim' }` — checks `iss === issuer` (issuer comparison ignores a single trailing slash), `aud` equals `audience` or contains it in an array, `exp > nowSeconds`, and, when `nonce` is non-null, `claims.nonce === nonce`. Missing `iss`, `aud`, `exp`, or `sub` yields `missing_claim`.
- `verifyIdToken(args: { idToken: string; discovery: OidcDiscovery; audience: string; nonce: string | null; nowSeconds?: number; fetchImpl?: typeof fetch }): Promise<IdTokenClaims>` — decodes the payload, fetches the JWKS, imports the JWK matching the token's `kid` header as an RS256 `CryptoKey` via `crypto.subtle.importKey('jwk', jwk, { name: 'RSASSA-PKCS1-v1_5', hash: 'SHA-256' }, false, ['verify'])`, verifies the signature over `header.payload` with `crypto.subtle.verify`, and **only then** calls `validateIdTokenClaims`. It throws `Error('id_token_signature_invalid')` when the signature does not verify and `Error('unknown_signing_key')` when no JWKS entry matches the `kid`.

The header segment of the `id_token` is decoded the same way to read `kid` and `alg`.

import { ORPCError } from '@orpc/server'
import { env } from '../env'
import { hasAdminGroup, type SessionRecord } from '../auth/session'
import type { ApiContext } from './context'

export async function requireSession(context: ApiContext): Promise<SessionRecord> {
  if (!context.session) throw new ORPCError('UNAUTHORIZED', { message: 'Authentication required' })
  return context.session
}

export async function requireAdmin(context: ApiContext): Promise<SessionRecord> {
  const session = await requireSession(context)
  if (!hasAdminGroup(session, env.authentik.adminGroup)) {
    throw new ORPCError('FORBIDDEN', { message: 'Admin group required' })
  }
  return session
}

- [ ] **Step 7: Write `apps/api/src/auth/routes.ts`**

`handleAuthRoutes(request, url)` switches on `url.pathname`:

- `/api/auth/login` — if `!env.authentik.isConfigured`, return `503` with the JSON body `{ "error": "authentik_not_configured", "message": "Set AUTHENTIK_CLIENT_ID and AUTHENTIK_CLIENT_SECRET." }`. Otherwise generate `state`, `nonce`, and a PKCE pair; store `{ state, nonce, verifier, createdAt }` JSON-encoded in the `dasa_oauth` cookie with `httpOnly: true`, `secure: true`, `sameSite: 'Lax'`, `path: '/api/auth'`, `maxAge: 600`; then 302-redirect to `buildAuthorizeUrl(...)` with scope `openid profile email groups`. The `returnTo` query parameter is accepted and stored in the `dasa_oauth` cookie alongside the state, nonce, and verifier. It must be a same-origin path — it must start with a single `/` and must not start with `//`. Anything else is discarded and the stored value defaults to `/`.

  The `secure` flag is driven by `env.publicOrigin.startsWith('https://')` so plain-HTTP local development still receives the cookie.

- `/api/auth/callback` — read the `dasa_oauth` cookie and the `state` query parameter. If the cookie is missing, or `state` does not match the stored state, respond `400` with `{ "error": "invalid_state" }`. Exchange the `code` for tokens, `verifyIdToken` with the stored nonce, then `createSession` from the claims (`sub`, `email`, `name`, `groups`), set the `dasa_session` cookie (`httpOnly`, `secure` per the same rule, `sameSite: 'Lax'`, `path: '/api'`, `maxAge` from `env.sessionTtlDays`), clear the `dasa_oauth` cookie, and 302-redirect to the stored `returnTo` when it is a valid same-origin path, falling back to `/` otherwise.

  Every failure path returns a specific JSON error code — `invalid_state`, `token_exchange_failed`, `id_token_invalid`, `authentik_not_configured` — and never leaks a token, secret, or the raw provider body.

- `/api/auth/logout` — read the session cookie, `revokeSession` it, clear the `dasa_session` cookie, and 302-redirect to `env.publicOrigin`.

- `/api/auth/session` — return `{ authenticated: boolean, groups: string[], isAdmin: boolean }` for the current session, or `401` when there is none.

- The `/api/auth/login` route also accepts a `returnTo` that names where the user was heading. The admin layout uses it so a visitor who opens `/admin` while signed out lands back on `/admin` after the Authentik round trip instead of on the home page.

- Any other `/api/auth/*` path — `404`.

```ts
export function slugify(input: string): string {
  return input
    .toLowerCase()
    .replace(/[^a-z0-9]+/g, '-')
    .replace(/^-+|-+$/g, '')
    .slice(0, 80)
    .replace(/-+$/g, '')
}
```

`deriveExcerpt` strips markdown link syntax with `.replace(/\[([^\]]*)\]\([^)]*\)/g, '$1')`, removes heading markers, emphasis markers, inline-code backticks, and blockquote markers, collapses runs of whitespace into a single space, trims, then truncates to `maxLength` on the last space before the limit and appends `…` when it had to cut.

`readingTimeMinutes` splits on whitespace, filters empties, and returns `Math.max(1, Math.ceil(count / 220))`.

`renderMarkdown` uses `marked.parse(markdown)` to produce HTML, runs it through `sanitizeHtml`, and highlights fenced code blocks with shiki's `codeToHtml` for the `github-dark` theme. Because shiki is asynchronous, `renderMarkdown` is async. `sanitizeHtml` removes `<script>`, `<style>`, `<iframe>`, `<object>`, `<embed>`, and `<form>` elements together with their inner content using a case-insensitive regex that matches the opening tag, any content, and the closing tag, and rewrites `href`/`src` values beginning with `javascript:` (case-insensitive, allowing leading whitespace) to `#`.

- [ ] **Step 9: Write `apps/api/src/modules/posts/repository.ts` and `service.ts`**

`repository.ts` holds the raw Drizzle queries, each taking an optional executor so a transaction can be passed in:

- `listPublishedPostsRepo(executor, { sources, tag, year, q, limit, before })` — selects posts where `status = 'published'` **and** `published_at <= now`, ordered by `published_at desc, id desc`, applying `sources` with `inArray`, `tag` with `arrayContains` on the `tags` column, `year` with `sql`extract(year from published_at) = ${year}`, and `q` with `ilike` on `title` or `excerpt`. Returns `{ rows, total }` where `total` is a separate `count()` over the same filter without the limit.
- `findPublishedBySlugRepo(executor, slug)` — selects by slug with `status = 'published'` and `published_at <= now`.
- `findPublishedNeighboursRepo(executor, publishedAt, id)` — one row before and one row after in `published_at desc, id desc` order.
- `findRelatedRepo(executor, post, limit)` — published posts sharing at least one tag, excluding the post itself.
- `adminListPostsRepo(executor, { status, source, limit })`
- `insertPostRepo(executor, values)`
- `updatePostRepo(executor, id, values)`
- `deletePostRepo(executor, id)`
- `findPostByIdRepo(executor, id)`
- `slugExistsRepo(executor, slug, excludeId?)`

`service.ts` composes the repository with the domain rules:

- `adminCreatePost` derives `excerpt` from `body` when the input excerpt is null, computes `readTimeMin`, and inserts with `status: 'draft'`.
- `adminPublishPost(id, publishedAt = new Date())` computes the base slug from the title (or the post's stored slug), then ensures uniqueness: while `slugExistsRepo` returns true for the candidate, append `-2`, `-3`, and so on. It sets `status: 'published'`, `published_at`, `slug`, and `updated_at`.
- `adminUnpublishPost(id)` sets `status: 'draft'` and clears `published_at` **and** `slug`, so the slug is free for reuse and the post disappears from the public feed.
- `adminUpdatePost(id, input)` applies only the provided fields; when `body` changes and the input has no explicit excerpt, the excerpt is regenerated.
- `adminDeletePost(id)` deletes the row.
- `listPublishedPosts` maps rows to `PostSummary`, computing `nextCursor` as the base64url of `${publishedAtIso}|${id}` of the last returned row when a further row exists, and `null` otherwise.
- `getPublishedPostBySlug` returns `null` for a missing, draft, or future-dated post, and attaches `prev`/`next` summaries and `bodyHtml` from `renderMarkdown` when `body` is non-null.

The `source` column for a LinkedIn post is `'linkedin'` and `linkedin_meta` is `{ permalink, postedAt }`.

- [ ] **Step 7: Write `apps/api/src/integrations/github/sync.ts`**

`syncGitHub(options)`:

1. Calls `fetchPublicEvents(options.username, options.token, options.fetchImpl)`.
2. Flattens `events.flatMap(mapGitHubEvent)`.
3. For each draft, looks up an existing row by `(source = 'github', external_id = draft.externalId)`. If none exists, insert a row with `status = 'published'`, `published_at = draft.publishedAt`, `excerpt` derived from the draft title, `read_time_min = 1`, `tags`, `github_meta`, `external_url`, and `slug` = `slugify(draft.title)`. If a row exists, update its `title`, `github_meta`, `external_url`, and `updated_at`. Count `created` and `updated` accordingly.
4. `skipped` counts drafts whose title slugifies to an empty string (those are ignored, because a post needs a title).
5. Returns `{ created, updated, skipped, error: null }`.
6. After the upserts succeed, write the repository snapshot to the `settings` table under the key `github:overview`. The snapshot is `{ repos, languages, totalCommits, activity, syncedAt }`: `repos` comes from `fetchRepos` mapped to `{ name, description, url, language, stars, forks, updatedAt }` and filtered to exclude forks; `languages` maps each language to the number of repositories using it; `totalCommits` is the sum of the `size` field of every `PushEvent` payload seen in this sync; `activity` is the per-day commit count for the last 90 days, derived from the `created_at` of each `PushEvent`; `syncedAt` is the current time. The `featured` flag is **not** stored in the snapshot — it is applied at read time from the `github:featured` key, so toggling a featured repository takes effect immediately without a resync.

On any thrown error, catch it, and **also** update the `sync_state` row for source `github` with `lastRunAt = new Date()`, `lastStatus = 'error'`, `lastError = String(error).slice(0, 500)`, then return `{ created: 0, updated: 0, skipped: 0, error: String(error).slice(0, 500) }`. On success, set `lastStatus = 'ok'` and `lastError = null`. A failed sync must **not** overwrite an existing `github:overview` snapshot: the last good snapshot stays readable, and the admin panel shows the error separately.

`startGitHubScheduler(intervalMinutes)` calls `syncGitHub` immediately, then `setInterval` at `intervalMinutes * 60_000`. Call `.unref()` on the interval handle so it never keeps the process alive. When `env.nodeEnv === 'test'`, return without scheduling.

2. **The repository** — create `Dasa122/dasa122.net`, add it as the remote, and push the branch.
3. **The Coolify project** — create the project `dasa122.net`; create a Coolify-managed PostgreSQL with `is_public: false`; create the `api` application with the FQDN `https://dasa122.net/api` and the build pack `dockerfile` with the dockerfile path `apps/api/Dockerfile`; create the `web` application with the FQDN `https://dasa122.net` and the dockerfile path `apps/web/Dockerfile`.
4. **The environment variables** — the exact list for each application, taken from the spec's table. 5. **The reverse proxy** — the Caddy block on the proxy host: the apex `dasa122.net` is **not** covered by the `*.dasa122.net` wildcard certificate, so Caddy must obtain a separate certificate for the apex. HTTP-01 works because Caddy owns port 80 on that IP. The block forwards to the Coolify Traefik at `10.0.1.80:443` with `header_up Host {host}` and `tls_insecure_skip_verify`, matching the existing pattern used by the other hostnames on that host. The API needs **no** extra DNS record and **no** extra certificate — it shares the apex under the `/api` path prefix.
6. **Verification** — the exact commands to run from the LAN: `curl -sI https://dasa122.net/` (expect `200`), `curl -s https://dasa122.net/api/health` (expect JSON with `"database":"up"`), `curl -s -o /dev/null -w '%{http_code}' https://dasa122.net/healthz` (expect `200`), and `curl -s https://dasa122.net/api/doc/openapi.json` (expect the OpenAPI document). Then sign in to `https://dasa122.net/admin` and confirm the Authentik round trip lands back on `/admin`.
